X2  BUG-06: NVRTC architecture hardcoded
==============================================================================================
  cuda_backend.py: opts = [b"--std=c++14", b"--gpu-architecture=compute_86"]
  this device reports compute capability 8.6 -> correct flag would be compute_86
  the device capability is queryable in 3 lines but is never queried.

  PTX target         compiles     loads on this sm_86 device
  ---------------- ---------- ------------------------------
  compute_70              yes                            yes
  compute_80              yes                            yes
  compute_86              yes                            yes
  compute_90              yes             NO (driver rc=218)

  PTX is forward-compatible: compute_86 PTX JITs onto NEWER devices, so an
  H100 (sm_90) would in fact work. It is OLDER targets that fail -- A100
  (sm_80), T4 (sm_75), V100 (sm_70) cannot load compute_86 PTX.
  CONFIRMED as a real portability defect, with that one correction to scope.

X3  BUG-07: are device allocations protected against an exception mid-loop?
==============================================================================================
  'try:' occurrences in run_hogbom_cuda_native  : 0
  'finally:' occurrences                        : 0
  cuMemFree_v2 calls                            : 8
  The 8 cuMemFree_v2 calls sit on the straight-line path after the loop, so any
  exception raised inside the loop leaks every device buffer for the life of
  the process. CONFIRMED.
  Note this compounds with F8: once return codes ARE checked and calls raise,
  the leak becomes reachable on any CUDA error, not just on a Python bug.
